# **Завдання 4: Docker**

## **Опис завдання:**

1. Створіть власний проект, що включає:
   - **Django** — для вебзастосунку
   - **PostgreSQL** — для збереження даних
   - **Nginx** — для обробки запитів
2. Використайте `Docker` і `Docker Compose` для контейнеризації всіх сервісів.
3. Запуште проект у свій репозиторій на `GitHub` для перевірки.

## **Кроки виконання завдання:**

1. **Створіть структуру проекту `Django` в `Docker`:**
   - Ініціалізуйте новий Django-проект (назва проекту на ваш вибір)
   - Налаштуйте **PostgreSQL як базу даних**
   - **Додайте Nginx** для проксирування трафіку

2. **Створіть Dockerfile для Django:**

Ваш Dockerfile повинен:

   - Використовувати образ `Python 3.9` або новіший
   - Встановлювати всі необхідні залежності з **requirements.txt**
   - Запускати `Django`-сервер у контейнері

3. **Створіть docker-compose.yml:**

У **docker-compose.yml** опишіть усі три сервіси:

   - *web* але насправді назвав ***django*** — `Django`-застосунок
   - *db* — `PostgreSQL` для збереження даних
   - *nginx* — вебсервер для обробки запитів

***Налаштуйте Nginx***

Створіть файл **nginx.conf** у папці **nginx** з таким вмістом:

```nginx
   server {
      listen 80;

      location / {
         proxy_pass http://django:8000;
         proxy_set_header Host $host;
         proxy_set_header X-Real-IP $remote_addr;
         proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
      }
   }
```

4. **Протестуйте проект локально:**

Запустіть проект за допомогою команди:

```bash
   docker-compose up -d
```

Переконайтеся, що:

   - Вебзастосунок доступний за адресою [http://localhost](http://localhost)
   - Підключення до бази даних `PostgreSQL` працює

5. **Запуште проект у GitHub:**

   - Створіть нову гілку lesson-4 у вашому репозиторії
   - Завантажте всі файли вашого проекту в репозиторій
   - Використовуйте такі команди для завантаження змін:

```bash
   git checkout -b lesson-4
   git add .
   git commit -m "Add Dockerized Django project with PostgreSQL and Nginx"
   git push origin lesson-4
```

**проект має включати:**

   - `Dockerfile`
   - `docker-compose.yml`

Конфігураційний файл `nginx.conf`:

   - `Django`-код із налаштуваннями бази даних `PostgreSQL`


**Структура проекту:**

```md
goit-devops-hw-04/
├── .env                  # Секрети - не додаємо в Git
├── .env.example          # Шаблон конфігурації (містить тестові дані для перевірки ДЗ)
├── .gitignore            # Правила ігнорування
├── start.cmd             # Пускач для Windows
├── start.sh              # Розумний пускач для Mac/Linux/Git sh
├── docker-compose.yml    # Головна оркестрація
├── Dockerfile            # Інструкція для збірки Django
├── entrypoint.sh         # Скрипт ініціалізації (Магія: чекає базу, робить міграції)
├── requirements.txt      # Залежності Python
├── nginx/
│   └── nginx.conf        # Конфіг проксі (з урахуванням статики)
└── core/                  <-- Зовнішня папка (контейнер проекту)
    ├── manage.py          <-- Головний скрипт управління
    └── core/              <-- Внутрішня папка (головний Python-пакет проекту)
        ├── __init__.py
        ├── asgi.py
        ├── settings.py
        ├── urls.py
        └── wsgi.py
```

**🛡️ Security Note:**

Для зручності перевірки цього домашнього завдання, файл `.env.example` заповнено готовими тестовими значеннями (щоб ви могли запустити проект однією командою). У реальному Production-проєкті цей файл містив би лише назви констант, а справжні секрети Я б передавав через CI/CD пайплайни.

## 🚀 Як запустити проект (Швидкий старт)

Цей проект оснащено розумними пускачами (Smart Launchers), які автоматично перевіряють стан Docker, визначають вашу ОС та безпечно розгортають середовище. Вам не потрібно вручну вводити довгі команди `docker-compose`.

### 🪟 Для користувачів Windows

У вас є два варіанти запуску:

**Варіант А (Графічний):**
Просто двічі клікніть на файл `start.cmd` у папці проекту. Скрипт автоматично знайде ваше середовище (Git Bash або WSL) і безпечно запустить проект.

**Варіант Б (Через термінал):**
Відкрийте термінал (CMD, PowerShell або термінал у VS Code) у папці проекту та виконайте:

```cmd
.\start.cmd
```

### 🍏🐧 Для користувачів macOS та Linux

Відкрийте термінал у корені проекту.

1. Надайте скрипту права на виконання (це потрібно зробити лише один раз - але Я вже все це зробив. Це на випадок, якщо раптом сталась непередбачувана обставина...):

    ```sh
    chmod +x start.sh
    ```

2. Запустіть проект:

    ```sh
    ./start.sh
    ```

---

### 🌐 Перевірка працездатності

Після успішного відпрацювання скрипта:
1. Вебзастосунок Django буде доступний за адресою: [http://localhost](http://localhost)
2. База даних PostgreSQL автоматично підніметься на порту `5432` (міграції будуть застосовані автоматично завдяки `entrypoint.sh`).

Щоб зупинити проект, виконайте в терміналі:

```sh
docker compose down
```

*(або `docker-compose down` для старих версій)*
